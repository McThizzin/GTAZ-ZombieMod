# AGENTS.md

GTA V zombie mod (GTAZ). A .NET Framework 4.8 ScriptHookVDotNet3 (SHVDN3) script and LemonUI menu that deploys directly into the GTA V `scripts/` folder.
The language is C# targeting .NET Framework 4.8.
When asked to write code, use the `GTA`, `GTA.Native`, and `GTA.Math` namespaces.
For calling game functions, use the `Function.Call(Hash.XXXX, args)` syntax.
For the menu, use the LemonUI MenuPool and SizedAndSizedMenuItem classes.
**Do not use outdated SHVDN 1 or 2 syntax.**

## Build & run
- Build: `dotnet build .\GTAZ\ZombieMod.csproj` (only project; no tests, no lint, no CI).
- `GTAZ/ZombieMod.csproj` hardcodes `<OutputPath>` and both `<HintPath>`s to `D:\SteamLibrary\steamapps\common\Grand Theft Auto V\`. The build FAILS unless GTA V is installed there with `ScriptHookVDotNet3.dll` in the game dir and `LemonUI.SHVDN3.dll` in `scripts\`. Output `ZombieMod.dll` lands directly in the GTA V scripts folder.
- No unit tests — verification requires running GTA V. Runtime artifacts: log `scripts/GTAZ.log` (deleted/recreated each session), saves `scripts/GTAZ/PlayerData_*.ini`, config `scripts/GTAZ/ModConfig.ini`.
- `ModSamples/` holds reference mods (GangMod, SimpleZombies, Trainer) `NATIVES/` holds GTA V native reference — NOT part of the build.

## Architecture
- Only `ModCore` extends `Script` (GTAZ/ModCore.cs). Everything else is a plain class; `ModuleManager` (GTAZ/ModuleManager.cs) ticks them in fixed order every frame. Never call `Script.Wait()` in a constructor — blocking init goes in first-tick actions (see `ModuleManager._tickActions`).
- Same trap, different shape: never read `Game.Player.Character`-anything in a constructor either — SHVDN3 can run constructors before the game is fully ready, and relationship natives issued that early are **silently dropped** (the `SET_RELATIONSHIP_BETWEEN_GROUPS` calls don't stick; playtest logs showed the ctor group *matching* the live group, so it's an early-native-drop, not a phantom group — see lesson 33). Player-facing relationship stances (survivor/recruit Companion, bandit Hate) were bound that way and the real `PLAYER` group stayed Neutral → survivors shot the player. Fix: `PedExtensions.EnsurePlayerFacingRelationships()` — a one-shot, idempotent re-assert against the live player group on the first tick (see `ModuleManager.Initialize`). Lesson 33.
- `PedBudgetManager.Instance` (GTAZ/Core/PedBudgetManager.cs) is the #1 constraint: slot-based budget, `GlobalBudget = 120`, per-category minimums, priority/distance eviction. API is `TryRequestSlot` / `TryRequestAndSpawn` / `ReleaseSlot` / `PeriodicRescore`. NOTE: DOCS/01-Architecture.md documents an older `TryAllocate/Release/Rebalance` API with a 200 budget — the code is the source of truth.
- `SpawnRequestQueue.Instance` (GTAZ/Core/SpawnRequestQueue.cs) defers spawns: 3 grants/pass, 8s TTL, priority aging. Spawn via `SpawnRequest` (set `SpawnFactory` + `OnGranted`).
- `ZombieSystem.OnTick` early-returns while the player is dead or `!Game.Player.CanControlCharacter` — keep ped-touching code behind this guard.
- `HordeSystem` (GTAZ/Systems/HordeSystem.cs) runs horde events: wandering hordes on a timer + once-per-night sieges. While any horde is active it borrows the reserved FactionNpc/Survivor budget minimums (`PedBudgetManager.RebalanceForHorde`, **ref-counted** — territory fights hold a second ref so hordes and fights coexist without stacking minimums; minimums restore when the last ref releases). Horde members live in `HordeSystem`'s own list — NOT `ZombieSystem._activeZombies` — so `CleanupDistantZombies` never despawns them. Horde and ambient spawns share one `SpawnRequestQueue` owned by `ZombieSystem`; ambient spawning is throttled in `TryAmbientSpawn` (distance + target count), not globally suppressed, so ambient zombies keep spawning while a horde is live (previously `SetAmbientSuppressed` killed all ambient spawns for the horde duration and left the map empty if you couldn't find the horde). `Announce()` is the ticker + distant gunfire + cam shake only — it does NOT drop survivors at the horde site (playtest 2 removed the hardcoded `SpawnAt(position, 2)` drop; horde members are player-only so the site survivors were pointless meat that shot the passing horde, and they ignored the player's `SurvivorCount` setting). Hordes never stage or march through ANY territory (`FactionSystem.IsInAnyTerritory` — staging, wandering destinations, and member fade all check it). NOTE: `IsInAnyTerritory` matches BOTH the game zone (`zone.IsInZone`) AND the visible `TerritoryRadius` ring around each zone's center — the minimap ring is what players see, and hordes were spawning inside it while outside the (smaller) game zone. Design: DOCS/09-Development-History.md §Phase-3.
- **Phase 5 horde overhaul** (DOCS/12-Horde-Overhaul.md): wandering hordes **sweep across the player** — destination goes on the far side of the player (spawn→player direction + jitter, `HordeSpawnDistanceMax + 200m`), `Heading` stored and kept by the flowing march. Movement is a **cadence-based flow** (`FlowPushInterval` = 300 frames), not arrive-and-wait: every push re-points the destination ~140m ahead of the horde center (`GetHordeReference` = the **Horder** when alive, else centroid), stragglers > 25m get reeled back to the center with **hysteresis** (pull trigger >25m, release <15m, tracked by `ZombieAI.HordePullingBack` so a boundary-hovering member can't flip its march target every tick and stutter — lesson 54), and the march task has the lesson-50 stuck-speed fallback. **Horde members only ever pursue the PLAYER** — `FindBestTarget` skips the nearest-ped scan while `HordeMoveTarget` is set, so random peds never drag the sweep off-course into a detour (and gunfire), lesson 53. **Engagement cascade**: when any member is Chasing/Attacking, the march re-points at the player (within `HordeEngageDistance`) so the whole horde converges — stopped at the territory edge when the player stands inside a zone (`ResolveSurgeTarget`). Every horde spawns one **Horder** (`HorderAI`, `g_m_m_zombie_02`, removed from `RunnerModels` so ambient never spawns it, counts as a `size` member): the center/march/blip reference, **immune while any OTHER member lives** — proofs applied at construction AND re-asserted/cleared every tick (`HordeAlive` set by HordeSystem, lessons 51/35/53), so clearing the horde makes it killable — and killing it pays out a body-armor pickup (`HorderAI.OnDeath` → `World.CreatePickup(PickupType.Armour, Ped.Position)`, only on an actual kill; distance/territory fades use `FadeOut` so they drop nothing). **A horde isn't depleted while its spawns are still queued** (`ActiveHorde.PendingSpawns`, incremented per enqueue, decremented per grant and per request-expiry — `IsDepleted = Members.Count == 0 && PendingSpawns == 0`), because `ZombieSystem.ProcessQueue` runs before `HordeSystem.OnTick` in `_tickActions`: on the StartHorde frame the grants haven't landed yet, and counting `Members` alone instantly "depleted" every scheduled horde and orphaned its later-granted members (lesson 52). The distance/territory **fade loop skips engaged members** (Chasing/Attacking) — fading a fighting member mid-fight dropped the immunity's "other member alive" count while the horde was visibly still fighting. Members materialize as a tight pack (4–12m cluster around the spawn center, `HordeSpawnDistanceMax` 220m default). Hordes have a **skull map blip** (`BlipSprite.TeamDeathmatch` ID 378, `ShowHordeBlips`, anchored on the Horder/centroid).
- Territory events (FactionSystem orchestration — the state machine lives in `GTAZ/Systems/TerritorySystem.cs`, spawn construction in `GTAZ/Systems/FactionSpawner.cs`, and FactionSystem keeps the cross-system surface as thin delegates like `IsInAnyTerritory`/`HomeFaction`/`SurrenderCurrentZone`) are per-area horde mechanics — territories are event-driven ground. **Ambient faction members and The Families' gang-car encounter only spawn OUTSIDE territory radii** (`TryAmbientSpawn`/`TryFamiliesEncounter` skip `IsInAnyTerritory`; the encounter never anchors to a held zone). `TryFamiliesEncounter` (the former `TryBanditPatrol`) spawns 1-2 gang cars full of GSF crew (`FactionRole.Crew`, 4-door cars only — `_familiesCars` = impaler5/superd/cavalcade3; the old faction3/voodoo2 were 2-doors and every rear-seat warp failed, lesson 46) every `BanditPatrolIntervalMinutes` (the "Families Encounter Interval (min)" slider) and fires a ticker. The crew cruises until it spots the player (120m + LOS), then chases them in the cars — driver `TASK_VEHICLE_CHASE` (aggressive ramming), passengers `TASK_VEHICLE_SHOOT_AT_PED` drive-by (NOT `TASK_DRIVE_BY` — its own native doc says "doesn't seem to do anything", lesson 48); the player is their only focus (ambient zombies never distract them). Crew peds set `BlockPermanentEvents` in `SpawnCrewForCar` (NOT `MakeFactionLike` — shared) so the engine never hijacks a passenger out of the car, and the AI re-warps a member whose initial `TASK_WARP_PED_INTO_VEHICLE` failed (`TryReWarpCrew`). Crew members are armed in the car via `SET_CURRENT_PED_VEHICLE_WEAPON` right after `MakeFactionLike` — `MakeFactionLike`'s `Weapons.Select` only arms the on-foot slot, and a passenger without a vehicle weapon is unarmed in the car (the "flip the player off" reaction) and `TASK_VEHICLE_SHOOT_AT_PED` has nothing to fire; the task's p2 is a shoot range (CrewDriveByRange), not a flag — passing 0 meant never in range (lesson 48). They pile out for a genuine on-foot stand-off only — player on foot, slower than a jog, standing within 15m for ~2s — or when the driver dies; the exit task is issued ONCE (an exit-pending flag stops `TASK_LEAVE_VEHICLE` being re-issued every 6-frame pass, which restarted the exit animation, and fires `TASK_COMBAT_PED` the instant the member is on foot — no post-dismount idle, lesson 47). On the stand-off the driver's car is RELEASED to the game (parked + grab-able, engine reclaims later — no piles; `DeleteVehicle` is occupant-aware so a car with living crew aboard is never deleted out from under them). After a stand-off, `TASK_COMBAT_PED` is re-pointed at the player on a ~5s cadence so native retargeting onto a zombie swarm can't hold the crew off the player (zombies still aggro the crew — mutual Hate — no truce). Outrunning them past ~300m for ~4s makes them give up and drive off (faded by the normal despawn). **Owned-zone raids are timer-only**: `UpdateTerritoryFights` fires a `TerritoryFightWaveSize` raid near a player-owned zone when `TerritoryFightCooldownMinutes` (the "Territory Attack Interval (min)" slider, default 15) elapses; no kill acceleration — and the `FightCooldownTicks` gate MUST stay in front of `StartTerritoryFight` (round 5 lost it with the quota condition and raids looped every tick). **Hostile-zone defense waves escalate with kills**: `RegisterBanditKillNearTerritory` counts the zone-holder faction's defender deaths within `TerritoryRadius` of each hostile zone, and when `TerritoryFightKillQuota` is met `SpawnReinforcementWave` tops defenders back up to `OutpostDefenderCount` (never exceeds it) — capped per visit by `TerritoryFightReinforcementWaves` (the "Defense Reinforcement Waves" slider, default 3, reset on leaving the zone) so a hostile zone is always clearable (round 4 stacked a full `TerritoryFightWaveSize` on top of the base defenders and was uncapturable). Red ticker + `GTAZ.log` line, and `FightKills` resets when the player leaves. The raid end-check stays open (`PendingRaiderSpawns` on the zone, incremented per queued raider, decremented on spawn-grant/expire) so a raid can't "repel" itself 3s in — the 300-tick grace expired before the queue (3 grants/pass, 8s TTL) put raiders on the ground. Hostile zones also respawn defenders on `DefenderRespawnCooldownSeconds`, so a takeover attempt fights respawning defenders + a bounded number of escalating waves. **Territory-bound peds (any `HomeZone`) are marked essential at spawn** (`npc.MarkEssential()` in `SpawnFactionPed`) — without it the borrowed horde budget drops the FactionNpc minimum to 0 and distant defenders get budget-evicted mid-fight, so waves despawned without fighting and zones captured after a couple of kills ("2 groups of 10 spawned, 3 kills, captured"). **Capture and save-restore grant the full raid cooldown** (`FightCooldownTicks = TerritoryFightCooldownMinutes * 3600`) — setting 0 made a just-taken zone get raided the same second as capture. **`CountActive` counts only `HomeZone == null` peds** so defenders don't starve ambient spawns near a faction's own turf (which hid The Lost bikers). Capture = kill defenders, hold the cleared zone past a 1s grace (`ResistTicks >= 60`), ownership flips **instantly** — the hold-timer is gone (`ZoneCaptureTime`/`ZoneCaptureRate` were removed in the mapping pass; a cleared zone at the `MaxPlayerZones` cap stays contested instead of capturing). **Leave grace**: stepping out of the hostile ring freezes the takeover attempt for `TerritoryLeaveGraceSeconds` (only while "in-flight" progress exists — FightKills, queued/respawning defenders, `ResistTicks`, or `CaptureInProgress`; a zone with no progress resets instantly), with a centered on-screen "Return to {zone} to continue the fight - Ns" countdown (`FactionSystem.GetActiveLeaveGraces()` → `MenuManager.DrawLeaveGraceCountdown`); re-entering cancels it, expiry resets the takeover state so it can't re-arm every away tick. Living defenders are never cleaned by the reset (persist to `FactionDespawnDistance`; fight resumes on re-entry). **Surrender is deferred**: the menu's surrender item arms `SurrenderPending` and the revert only executes once the player steps OUT of the owned ring — otherwise the newly hostile defenders pop on top of them (`UpdateZones` owned branch). Zone flips to `IsPlayerOwned` (guards + green safehouse blip; ambient zombie spawns suppressed via `IsPlayerOwnedZone`). Defenders vanish without registering a kill (despawn/eviction) → no quota → no waves, so `SpawnDefenders` logs `Defender wave FAILED to spawn ... no safe positions` when a wave queues nothing. Capture CANNOT be blocked by respawn timing: once the player clears a hostile zone past a 1s grace (`ResistTicks >= 60`), `TerritoryZone.CaptureInProgress` latches and stops BOTH kill-triggered reinforcement waves AND defender respawns until capture or the player leaves (the old 60s hold vs 25s respawn was mathematically uncapturable, so capture is earned by the clear itself, not by standing in the zone). `CaptureZone` logs `Zone captured: {DisplayName}`.
- `SurvivorSystem` (GTAZ/Systems/SurvivorSystem.cs) spawns armed human NPCs (fight vs flee chosen per-spawn by `SurvivorCowardChance`) through the budget/queue. Fighters use `TASK_COMBAT_PED`, cowards `TASK_SMART_FLEE_PED` (see GTAZ/AI/SurvivorAI.cs); both wander when no zombie is near. Survivors are `PedCategory.Survivor`; their relationship group hates Infected and is **Companion (0)** to the player in both directions (Survivor `FactionDef.RelationToPlayer = PlayerRelation.Ally` → Companion in `SetupFactionRelationships`), so they are damageable — killing one drops a weapon pickup (weapon → `PickupType` via `CREATE_PICKUP`, null model so the game picks the default weapon mesh) — but they never treat the player as a combat target, **even when the player damages them** (Respect (1) was tried and still retaliated on player damage — that was the "hostile until they join" bug; Companion never fights back; see lessons 27/30/32). `WorldSystem.ClearAmbientPopulation` skips them (`Ped.IsSurvivor()`). Survivors are transient encounters: they fade once the player moves past `SurvivorDespawnDistance` (default 300m) so exploring keeps producing fresh fights (permanent survivors/recruiting is Phase 4). Recruiting works on ANY green-blip survivor: `RecruitManager.TryToggleRecruit` (GTAZ/Systems/RecruitManager.cs — owns the recruit list + the SoftAimController consumer; FactionSystem delegates `TryRecruitAtCrosshair`/`DismissAllRecruits`) first looks up an existing `FactionNPC` for the targeted ped, else adopts the ambient `SurvivorAI` via `SurvivorSystem.DetachAmbientSurvivor` (deletes its blip/tracking, wraps it as a `FactionNPC` in `FactionRole.Recruit`) — previously ambient survivors hard-rejected with "must be a survivor." Recruits follow via an explicit `TASK_FOLLOW_TO_OFFSET_OF_ENTITY` on idle (1.2 speed, issued on mode transitions, never per-tick) — the game's formation AI alone didn't drive follow. `ConvertNearbyEngineNpcs` also re-arms ordinary engine-spawned civilians into survivors (capped at `SurvivorCount`) so civilians react to zombies instead of being oblivious — it skips `IsFactionPed()` peds (converting a bandit double-wrapped it and stacked a green Friend blip on its orange Enemy blip). Survivors show short-range green minimap blips (`BlipSprite.Friend`, gated by config `ShowSurvivorBlips`).
- Zombies show short-range red minimap blips (GTAZ/AI/ZombieAI.cs `UpdateBlip`, gated by config `ShowZombieBlips`); toggling the setting applies on the next tick.
- Zombies **do not flee while on fire** (molotovs, exploded cars) — they keep pressing the normal Wandering/Chasing/attack behavior while burning. Blocked in `MakeZombieLike` via config flag **430** `CPED_CONFIG_FLAG_IgnoreBeingOnFire` — flag 118 `RunFromFiresAndExplosions` (also set false) only stops fleeing *from* a fire threat, not the panic task issued when the ped itself is ignited (lesson 56). **Trade-off:** flag 430 also suppresses the engine fire's damage over time, so `ZombieAI.Update` re-applies scripted burn damage on a ~0.5s cadence while a zombie is ignited or standing in a fire pool (skipping fireproof peds like an immune Horder) — burning zombies keep attacking AND burn to death (lesson 57). The scripted `_fireFleeing` FleeFrom branch was removed (read as buggy scattering); a molotov's crowd-control is the burn damage, not panic.
- **Zombie speech/audio (lesson 59)**: `STOP_PED_SPEAKING(ped, true)` is per-ped and only mutes *ambient dialogue* — it can't silence the world (the silent-world impression is `ClearAmbientPopulation`) and never touched pain/death groans (those are `PLAY_PAIN` audio, `eAudDamageReason` DYING_MOAN=27/ENTERING_RAGDOLL_DEATH=14). `MakeZombieLike` sets `STOP_PED_SPEAKING` + `DISABLE_PED_PAIN_AUDIO(ped, true)` **once** at spawn (both persist) so the vanilla human pain/death screams never fire; `ZombieAI.Update` has no per-frame speech call. Scripted zombie sounds play via `PLAY_PAIN` and must **re-enable pain audio first** (`DISABLE_PED_PAIN_AUDIO(ped,false)` → `PLAY_PAIN` → re-disable; pain sounds are muted while disabled — SimpleZombies does the same). Gurgle cadence: `ZombieGurgleReasons` (WHEEZE=18/COUGH=19/WHIMPER=26/small+large grunts=31,32/DEFAULT) on `ZombieSoundInterval` (~10s), gated to `ZombieSoundRange` 45m of the player so a horde isn't a noise wall, `ZombieSoundChance` 40%. Death moan: scripted `PLAY_PAIN(ped, 27, 0f)` fired on the exact death frame in `Update` (`_deathMoanPlayed` guard), replacing the vanilla groan. No `scream_panic/terror/on_fire` reasons (human screams). Custom OGG audio is NOT script-playable in single-player (needs an AWC pack or external player) — deferred.
- Territory wave spawns are **player-mapped points keyed by the resolved game-zone name** (`Territories.txt` ↔ `TerritoryCatalog.GetWaveSpawns`; all 12 territories are mapped with 4 points each — see the file for the master list). Initial hostile-zone defenders spawn **near the zone center** (`SpawnUtils.FindSafePosition(zone.Center, 5f, 40f)`, same as survivor guards — the far mapped points sat up to ~400m out and got 3D-distance-cleaned without a kill, so zones fell with no waves, lesson 40); reinforcement/defense/raid waves pick a random mapped point via `GetWaveSpawn` (never a safe-position search — the points are player-verified safe, lesson 34), always excluding the point closest to the player so a wave never spawns on top of them. Hostile territories also get **ambient occupants of the holding faction** (`TerritoryOwnerAt` in `TryAmbientSpawn`) so hostile turf feels held while owned zones stay faction-free. `FactionAI` pursues the player for hostile factions: territory-bound peds (defenders/raiders/guards with a `HomeZone`) chase up to 300m, ambient patrols 60m, no LOS gate (`TASK_COMBAT_PED` paths around cover).
- Trainer god modes are **re-asserted every frame while enabled**, not set once on toggle — the game engine clears `SET_PLAYER_INVINCIBLE`/proof flags and vehicle proof flags on vehicle change, teleport, and entity re-creation, so a checked checkbox silently stopped working mid-session. `PlayerTrainer.GodModeOn`+`ApplyGodMode()` (called from `PlayerTrainer.Tick()`) and `VehicleTrainer.VehicleGodModeOn`+`ApplyVehicleGodMode()` (armed while out of a vehicle) — both called from `TrainerManager.Tick()`. Lesson 35.
- Debug overlays (MenuManager `Tick()` renders every frame, independent of menu visibility): `ShowPlayerCoordinates` (position/heading/zone + per-territory ring distances, for mapping) and `ShowStatusOverlay` (the Debug > Status text drawn live in the same top-left block, so it's watchable with the menu closed) both read from `ModConfig.Current` each frame; `ShowSpawnRadiusRing` + `SpawnRadiusRingMeters` draw a player-following minimap radius ring (blip recreated when the radius changes — radius blips take their size from the create call, `Scale` would set the ring to that many meters) to measure what a player-relative faction-wave spawn radius covers before the safe wave-spawn rework wires it in.
- **Faction roll-out** (all five factions live): the former Bandits are now **The Families** (Ballas/Aztecas/GSF gang models; internal Id stays `"Bandits"` so `BanditPatrolIntervalMinutes` and saves stay compatible). Military, Altruists (renamed from Cultists, internal Id `"Cultists"`), and The Lost are enabled (`AmbientSpawnWeight = 1f`) and **Hostile** to the player (shoot on sight). Territory holders come from Territories.txt via `TerritoryZone.HomeFactionId` + `FactionSystem.HomeFaction(zone)` — hostile-zone defenders/defense waves spawn as that faction, raids on player-owned zones come from the zone's home faction, `SurrenderZone` reverts to it, and `CaptureZone` hands it to Survivors. Altruists `SparesZombies` (cultist-zombie truce): faction→zombie Neutral, zombie→faction Hate — one-way via `SetRelationshipDirectional` in `SetupFactionRelationships`, re-asserted first-tick in `EnsurePlayerFacingRelationships` (the ctor can drop ALL relationship natives, lesson 33). Some Lost ambient/patrol spawns ride a hexer/daemon (`LostRiderChance`, `TryMountBike` — bikes are road-snapped via `World.GetNextPositionOnStreet`), drive-wander via `TASK_VEHICLE_DRIVE_WANDER`, and pursue the player ON the bike before dismounting to fight (`FactionAI` `Mode.VehicleChase`, `TASK_VEHICLE_DRIVE_TO_COORD_LONGRANGE`, dismount at ~20m); the bike is owned by `FactionNPC`, survives the rider's death (released to the game in `OnDeath` so it's rideable), and is deleted only on script despawn (`Cleanup`). All non-survivor factions shoot at reduced accuracy (`FactionDef.Accuracy`, default 35, vs survivor 60), and ambient/patrol faction spawns land 100-200m out (outside the 60m hostile pursuit range) instead of 40m. Survivor models are civilian-only (no zombie/faction overlap). The 3 territory relocations in Territories.txt are still pending (coordinates unchanged — existing 12 zones work as-is).
- Systems communicate via `GameEvents`/`ZombieEvents` (pub/sub), not direct references.
- **v1 polish (Phase 4 round 7)** — the last big bug classes:
  - **Ambient zombies standing idle**: (a) `UpdateTarget` kept a dead target as `Target` when nothing new was in range, so a zombie that killed an NPC stayed stuck in Attacking/Chasing against the corpse — it now drops it and falls back to Wandering (lesson 37); (b) `TASK_WANDER_IN_AREA` self-sustains *while running* but the engine can clear it, leaving `State` stuck in Wandering with a standing ped — the wander task is re-issued on a 2s cadence (`_wanderReissueTimer`), a gentle re-pick of a random point (lesson 37).
  - **Survivor guards standing around**: survivors run with `BlockPermanentEvents=false` (damageable for loot), so the engine hijacks their patrol with ambient scenario tasks; `FactionAI` only issued idle tasks on combat-exit, so a fresh guard had no task at all. Guards now `TASK_WANDER_IN_AREA` 100m (was `TASK_GUARD_CURRENT_POSITION` standing cluster); the idle task is issued on `_mode == Mode.None` (spawn/role-change) and re-issued after a stuck-scenario fallback (`Speed < 0.5f` for ~1.5s → `ClearAll()` + re-issue) (lesson 38).
  - **Autosave**: every `PersistenceManager.Save()` fires `DO_AUTO_SAVE` so weapons/money/ammo/stats persist in the GTA save; `PlayerData` has no weapon fields — the game save is the single source (lesson 39).
  - **Territory-bound peds** are cleaned by **zone-center distance** (`HorizontalDistance(zone.Center, player) > TerritoryRadius + FactionDespawnDistance`), never the old 3D ped-vs-player check, so defenders aren't evicted mid-fight without a kill (lesson 40).

## Gotchas (all hit before; see DOCS/08-Lessons-Learned.md for full detail)
- Spawn positions: use native `GET_SAFE_COORD_FOR_PED` (flags `2 | 4 | 8`), NOT `World.GetGroundHeight()` — unstreamed collision causes mid-air/embedded spawns and T-poses. `FindSafePosition` probes the terrain Z at each candidate first (`GET_GROUND_Z_EXCLUDING_OBJECTS_FOR_3D_COORD`, fallback `GET_GROUND_Z_FOR_3D_COORD`) and starts the search at `terrainZ + 1` (lesson 34: territory centers are hardcoded `Z=40`, so searching from the anchor Z fails on hillsides/basins — "no safe positions"). Rooftop rejection in `SpawnUtils.FindSafePosition` must probe `GET_GROUND_Z_EXCLUDING_OBJECTS_FOR_3D_COORD` (terrain with buildings excluded) — `GET_GROUND_Z_FOR_3D_COORD` returns the roof surface on a rooftop, so the old check was circular and bandits spawned unreachable on/inside roofs (lesson 33).
- **Territory range gates must use `SpawnUtils.HorizontalDistance` (X/Y only), never 3D `Length()` against `zone.Center`** — centers carry a flat `Z=40`, so 3D distance inflates every ring/raid/kill-radius check on hillsides and players visibly in a ring fall outside it (lesson 34). "Inside a territory" (`playerInside`, `IsPlayerOwnedZone`) is the visible `TerritoryRadius` ring, not the narrower game-zone test.
- Never use `CLEAR_AREA_OF_PEDS` — it deletes zombies too. Iterate nearby peds and `MarkAsNoLongerNeeded()` only non-zombies.
- `PeriodicRescore()` must run every tick or budget slots leak and spawns stop.
- Clipsets/anim dicts: `REQUEST_*` every frame until loaded before applying; fall back to `move_m@drunk@verydrunk`.
- Reissue AI tasks only when the task slot is free (`GET_SCRIPT_TASK_STATUS` != 1), or peds stutter and never act.
- "Self-sustaining" movement tasks (`TASK_WANDER_IN_AREA`, etc.) can be cleared by the engine at any time (blocked events, physics, task-slot reuse) — re-issue on a cadence, and always return a ped to its idle state when its target dies (lessons 37/38). This applies to EVERY movement task: the zombie Chasing follow-task had no reissue (only state-entry/target-change) and froze during the chaotic stand-off dismounts — it now has the same stuck-speed fallback (`Speed < 0.5f` ~30 behavior-ticks → re-issue follow), lesson 50. And when a reissue timer counts *behavior* ticks (gated by an `_updateInterval`), calibrate it against that interval (`120 / _updateInterval` ≈ 2s), not against frames — `120` raw was 6-12s.
- Peds with `BlockPermanentEvents = false` (survivors — needed so they take damage for loot) get their scripted tasks hijacked by ambient scenario tasks; a stuck-speed fallback (`Speed < 0.5f` ~1.5s → `ClearAll()` + re-issue idle) is required or guards/patrols freeze in place (lesson 38).
- Autosave: the mod save (`PlayerData_*.ini`) only carries mod state (position/heading/health/armor/territories). Weapons/money/ammo live in the GTA save — every `PersistenceManager.Save()` also fires `DO_AUTO_SAVE`; do NOT add weapon fields to `PlayerData` (lesson 39).
- Corpse reanimation was removed (Phase 4 round 3, user request) — `ZombieSystem.ScanForCorpseInfection`/`ReanimateCorpse` (the old `CLONE_PED`-based system), its `ZombieEvents`, config `Infection*` props, menu sliders, and `PlayerData.Infection` are all deleted. Do NOT re-add corpse infection; ambient + horde spawning is the intended zombie flow.
- Config flag 292 = `DisableAmbientSpeech`. Do NOT set it as `PED_FLAG_FREEZE` (some docs conflate them) — that causes instant T-pose.
- `unchecked((int)PedHash.X)` for hashes that overflow `int.MaxValue` (e.g. `Zombie01`).
- Game time: `GTA.Chrono.GameClock.Hour`, not `DateTime`.
- Reset clipsets to `move_m@generic` and disable ragdoll at `Health <= 30` to avoid the death-physics "rocket".
- `Data/Serialization/IniSerializer.cs` (renamed from `JsonSerializer` — it always wrote `.ini` via SHVDN `ScriptSettings`, not JSON). `ModConfig` (GTAZ/Core/Config.cs) round-trips through it: `ModConfig.Load()` runs in the `ModCore` constructor BEFORE the hotkeys are read, and `Save()` fires on settings-menu close and on `Aborted`. Writes `scripts/GTAZ/ModConfig.ini`. Stale claims about `config.json` are wrong.
- Zombies never climb ladders: config flag 146 = `CPED_CONFIG_FLAG_DisableLadderClimbing` stops the climb interaction, and `SET_PED_PATH_CAN_USE_LADDERS(ped, false)` stops the pathfinder routing onto ladders. Both set in `MakeZombieLike` (GTAZ/Extensions/PedExtensions.cs).
- LemonUI menus: set `Alignment = GTA.UI.Alignment.Right` on **every** `NativeMenu`, including dynamically-built submenus — each one is its own instance, and `Alignment.Center` throws (only Left/Right are valid). `MenuManager` and `TrainerManager` (root + PLAYER/VEHICLE/WEAPON/WORLD/SPAWN VEHICLE + the per-category vehicle spawn submenus in `BuildVehicleSpawnMenu`) all set it.
- GTA text components (passed to `ADD_TEXT_COMPONENT_SUBSTRING_PLAYER_NAME` / `BEGIN_TEXT_COMMAND_DISPLAY_TEXT`) interpret `~` as a **formatting token** (e.g. `~g~`, `~s~`) — a stray `~` prefix swallows the rest of the line and the text never renders. Never start a text string with a bare `~` (the leave-grace countdown was `"~ Return to {zone}..."` and showed nothing; lesson 56).
- Stale-DLL trap: if a removed feature (slider, config prop, code path) is still present in the running mod, the deployed `scripts\ZombieMod.dll` is stale — incremental builds can skip recompiling `Config.cs`/`MenuManager.cs`. Verify by grepping the removed string in the binary (`rg "ZoneCaptureTime" ZombieMod.dll`), and rebuild clean with `Remove-Item -Recurse -Force .\GTAZ\obj, .\GTAZ\bin` before `dotnet build`.
